# Guía de contenido

El contenido inicial se concentra en QA y automatización, pero V2 cambia el marco: cada unidad debe sentirse como una misión profesional, no como evaluación escolar.

## Quests

Cada quest debe tener:

- Contexto realista: cliente, sistema, síntoma y restricción.
- Conceptos asociados dentro del mapa de habilidades.
- Recompensa esperada en XP y monedas.
- Opciones redactadas como movimientos estratégicos.
- Feedback útil, narrativo y no juicioso.

## Buenas quests

Preferimos:

- Escenarios realistas de QA.
- Decisiones con criterio profesional.
- Distractores plausibles que revelen formas distintas de mirar el problema.
- Explicaciones que abren un siguiente paso.

Evitamos:

- Preguntas triviales de definición sin contexto.
- Trampas de redacción.
- Lenguaje de examen, castigo o urgencia.
- Comparaciones entre personas.

## Misiones

Una misión larga debe dividirse en capítulos:

1. Contexto del cliente.
2. Diagnóstico del problema.
3. Movimiento estratégico.
4. Recomendación.
5. Post-mortem o reflexión.

Cada misión completada debe poder generar evidencia reutilizable para el portafolio.

## Tips

Los tips son piezas breves para aprendizaje pasivo. Deben ser útiles sin exigir acción inmediata.

Tipos iniciales:

- Mito vs realidad.
- Caso real.
- Comparación.
- Consejo corto.

## Versionado

El contenido nunca se borra físicamente. Si una quest, misión o tip cambia, se crea una nueva versión y se conserva el historial.
